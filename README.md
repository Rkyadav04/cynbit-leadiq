# Cynbit LeadIQ

AI-assisted lead qualification and response drafting — assessment proof of concept.

## Overview

Cynbit LeadIQ takes a prospective customer's inquiry and presents a structured lead profile, a rule-based priority score, qualification gaps, and a suggested response for human review.

### Features

- Streamlit interface with sample inquiries
- Service categorization and extraction of business goal, stated budget, timeline, integrations, and missing information
- Deterministic Python priority scoring with reasons
- Editable and downloadable response draft
- Gemini API integration attempt with a clearly labelled local Demo fallback
- Pydantic validation and automated priority-scoring tests

## Important status and limitations

This is a prototype, not a production CRM or email automation system.

- During assessment testing, Gemini requests returned temporary server errors. Live Gemini analysis has not been verified as successful.
- When Gemini is unavailable, the app uses local keyword/regex heuristics. Demo fallback output is not generated by an LLM and may misclassify ambiguous inquiries.
- The priority score is a heuristic, not a calibrated probability of conversion.
- No email is sent and no CRM record is created or updated.
- The included automated tests cover priority scoring; they do not establish live model reliability, extraction accuracy, or business impact.
- Use synthetic/sample inquiries for demonstration. Production use would require privacy, security, and operational review.

## Requirements

- Python 3.13 or later is recommended for this prototype (tested locally with Python 3.14.3).
- pip
- A Gemini API key is optional for running the local fallback, but required to attempt live Gemini analysis.

## Setup on Windows PowerShell

From the project root:

```powershell
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt
```

Create a local `.env` file in the project root:

```dotenv
GEMINI_API_KEY=your_key_here
GEMINI_MODEL=gemini-3.8-flash
```

Replace `your_key_here` with your own key. Never commit `.env` or share your API key. If no key is configured, the app should use the labelled Demo fallback.

## Run the app

```powershell
.\venv\Scripts\python.exe -m streamlit run app.py
```

Open the local URL printed by Streamlit in your browser.

## Run tests

```powershell
.\venv\Scripts\python.exe -m pytest -v
```

The current scoring test suite contains three tests:
- Complete lead gets high priority
- Missing details get lower priority
- Score is never above ten

Record the actual output when running tests; do not assume tests passed after code changes.

## Security checklist

- Keep `.env`, `venv/`, `.venv/`, Python caches, and pytest caches out of Git.
- Commit `.env.example` with placeholder values only.
- Review `git diff` and `git status` before pushing.
- Never include real customer data, API keys, or credentials in the repository.

## Suggested demonstration

1. Start the app.
2. Select the “AI chatbot + CRM” sample inquiry.
3. Click **Analyze inquiry**.
4. Explain the service category, budget, timeline, integration, score, and missing information.
5. Point out whether the result is **Live Gemini** or **Demo fallback**.
6. Edit and download the suggested reply; explain that sending and CRM updates are not implemented.
